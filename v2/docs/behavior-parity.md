## Foundation evidence at Task 4

The independent Java 21 core now contains the normalized `BuildPlan` model and `RunLifecycle` owner with immutable context/snapshot records, covered by core unit tests. `CoreArchitectureTest` scans actual compiled production core classes, excludes tests, requires the model/lifecycle classes and rejects empty rule selections. It checks bytecode dependencies against Minecraft/Fabric/Mixin/Baritone and the Fabric adapter package, cycles between all core packages, and final fields in `core.model`. The exact package rules and limits are recorded in [CONSTRAINTS.md](../../CONSTRAINTS.md#enforcement-status-at-task-4).

The guard was proved with a temporary compiled production model class containing a non-final field: the focused architecture run failed on that field, then passed after the fixture was removed. These are foundation checks only. They do not prove deep immutability, reflective/path-based platform isolation, native movement, placement confirmation, refill, client/server behavior or any completed parity row. All gameplay preservation/correction statuses below remain pending.

## Actual entry path and supported commands

[MapArtClientMod](../../src/main/java/com/example/mapart/MapArtClientMod.java) registers the same [MapArtCommand tree](../../src/main/java/com/example/mapart/command/MapArtCommand.java) as `/mapart`, `/maprunner` and `/mapartrunner`. **All rows below apply to all three namespaces. All have status PRESERVE â€” pending.**

| Suffix after namespace | Reference behavior and v2 acceptance scenario |
|---|---|
| `load <path>` | Greedy path argument, normalized absolute path, readable format errors; load dimensions, targets, regions and material summary. Load each supported fixture and reject unsupported input clearly. |
| `unload` | Unload plan and clear session progress; useful no-plan feedback. Verify no active effects survive unload in v2. |
| `info` | Format/path, dimensions, placements, chunk regions, top ten material counts plus remaining-material count; counts use item stack quotient+remainder formatting. Compare known fixture counts. |
| `setorigin [<x> <y> <z>]` | Explicit integer coordinates or floored player position; requires a plan. Verify translated targets and preview. |
| `status` | Active grounded lane, phase, pending verification, refill and recovery flags; clear inactive feedback. Check during each activity. |
| `start` | Gets current session and settings, clears exhausted-supply state for a new run and starts full grounded sweep. Reject no-plan/unavailable/invalid starts usefully. |
| `pause` | Requires active run; retains paused progress and releases movement. Check pending work survives. |
| `resume` | Uses paused snapshot when valid, otherwise smart world-scan resume; reports which path. Preserve all unfinished targets (correction C1). |
| `stop` | Stops grounded runner and releases effects; permits a fresh start. Check during build, transition, refill and recovery. |
| `panic` | Cancels automation/refill and unloads current plan through coordinator panic cleanup, with idle/active feedback. Check controls and pending actions are released. |
| `supply add [<name>]` | Greedy optional name; arm registration, then right-click a container. Check ID, dimension, position and name persistence. |
| `supply list`, `supply remove <id>`, `supply clear` | List registered containers, remove ID >= 1 with missing-ID feedback, clear all with count. Round-trip persisted supplies. |
| `supply status` | Registered supply details and active refill state/target. Check before/during refill. |
| `settings` | Open settings screen on client thread; compare GUI controls/save/cancel with CLI settings. |
| `settings show` | Display HUD/overlay, sprint, pacing, reservation, timer, torch and air-place settings. Reference output does not list every stored field; preserve access to all keys below. |
| `settings set <key> <value>` | Case-insensitive keys, greedy value, validation/error feedback and persistence. Exercise valid/invalid bounds and reload. |
| `debug status` | Detailed current/last grounded state, resume selection, skipped lanes, approach/shift, counts, pending verification, leftovers and failure reason. Inspect successful, paused and failed runs. |
| `debug grounded-trace on\|off\|status` | Toggle/query trace (initially off); compare results with trace enabled/disabled. |
| `debug diagnostics on\|off\|status\|path` | Toggle/query structured diagnostics (initially on), expose log path. Verify useful failure evidence without changing decisions. |
| `debug grounded-recovery status` | Auto-resume setting, reason, lane/direction/pass, last safe progress/player position and stabilization/retry readiness. Inspect displaced-player recovery. |
| `debug mismatches [<limit>]` | Final-world mismatch scan; default 100, allowed 1..10000. Verify counts and sample positions against known missing/wrong blocks. |

There is **no registered `debug grounded-sweep start` or `debug sweep` command** in this reference. Old instruction/guide comments describing those routes are stale. `/mapart start` calls `GroundedSingleLaneDebugRunner.startFullSweep`; end-client-tick calls the grounded runner. `BuildPlanService` still delegates load/current-plan/current-session/unload and origin/panic services to [BuildCoordinator](../../src/main/java/com/example/mapart/plan/state/BuildCoordinator.java). Its plan/session/persistence responsibilities remain real v1 behavior; it is not classified as unused. The older single-lane runner is instantiated/ticked, but that does not establish a supported flight command.

## Settings and defaults

Every row is **PRESERVE â€” pending**. Exact keys/defaults come from [MapartSettings](../../src/main/java/com/example/mapart/settings/MapartSettings.java); validation/persistence comes from [MapartSettingsStore](../../src/main/java/com/example/mapart/settings/MapartSettingsStore.java). Settings survive restart in `config/mapartrunner/settings.json`; absent fields use defaults and malformed data falls back with a warning. Boolean values accept `true`/`false`; unknown keys/invalid values return errors. Width changes must keep `sweepTotalWidth = 2 * sweepHalfWidth + 1` (the reference validates each update).

| `laneStride` | `5` | Positive integer. Default five-block lane shift. |

| `torchGridEnabled` | `false` | Optional torch helper, separate from schematic target completion. |
| `torchGridSpacing` | `12` | Fixed at 12; setting attempts normalize/save 12 and report fixed-spacing error. |
| `torchGridWarnMissingTorches` | `true` | Missing-torch feedback. |
| `torchGridMaxPlacementsPerTick` | `1` | Integer 1..4. |
| `manualAirPlaceEnabled` | `false` | Optional player utility; independent of experimental Elytra flight. |
| `manualAirPlaceRender` | `true` | Target preview toggle. |
| `manualAirPlaceUseCustomRange` | `false` | Otherwise use vanilla block interaction range. |
| `manualAirPlaceCustomRange` | `5.0` | Numeric 0.0..6.0. |
| `manualAirPlaceRequireSneak` | `false` | Optional sneak gate. |
| `manualAirPlaceDisableWhileRunnerActive` | `true` | Gate while grounded build/refill/recovery owns controls. |

Per-row acceptance is setting through CLI, validating limits, persisting/reloading, and observing its production effect. GUI access is preserved where present: main screen has display toggles, sprint, delay/reservation sliders, timer and torch/air-place enable rows; dedicated torch/air-place screens expose their helper options. `Done` saves the current screen; `Cancel`/close discards its pending edits. A helper screen saved with `Done` persists immediately, even if the parent is later cancelled. See [MapArtConfigScreen](../../src/main/java/com/example/mapart/gui/MapArtConfigScreen.java), [TorchGridConfigScreen](../../src/main/java/com/example/mapart/gui/TorchGridConfigScreen.java), [AirPlaceConfigScreen](../../src/main/java/com/example/mapart/gui/AirPlaceConfigScreen.java), and [SettingsAndSupplyStoreTest](../../src/test/java/com/example/mapart/persistence/SettingsAndSupplyStoreTest.java).
