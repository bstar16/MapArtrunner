# MapArtRunner v2 early CI implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for implementation and independent review. Steps use checkbox syntax.

**Status:** authorized early slice of Task 14 in the approved parent roadmap, after Checkpoint A. Later game, soak and release gates remain pending.

**Goal:** Run the existing v2 unit, architecture and compilation checks automatically on relevant changes, preserving failure evidence.

**Architecture:** One conventional GitHub Actions job runs the independent v2 build through the existing wrapper. The v1 release workflow remains separate.

**Tech stack:** Java 21, Gradle 9.5.0, Jupiter 5.10.2, ArchUnit core 1.5.1, pinned Fabric platform from the parent design.

**Spec:** [approved v2 design](../specs/2026-10-28-v2-reliability-design.md). [Parent roadmap](2026-10-28-v2-reliability-plan.md#task-14-add-ci-gates-repeatability-and-release-evidence).

## Global constraints

- Keep all v1 source, build and release workflow inputs unchanged.
- Use the repository wrapper with `-p v2`; do not change platform or test dependency pins.
- Do not launch game tasks, accept the EULA, publish artifacts as releases, add schedules, use secrets or change branch-protection settings.
- Retain failing checks and assertions. Local validation is not proof of successful hosted CI execution.

## Review focus

- A failed Gradle command must remain a failed job through log capture.
- Test fixtures must be compiled even though client tests are not yet launched.
- Pull requests targeting a development branch must receive checks.
- Startup failures before XML generation must still retain the console log.
- Fork pull requests receive read-only checkout credentials and no secrets.

## Task 1: Add the early v2 checks workflow

**Files:** create `.github/workflows/v2-checks.yml`. No product code or test changes.

**Interfaces:** Ubuntu hosted job, Temurin Java 21, root wrapper; run `:core:check :fabric:compileJava :fabric:compileGametestJava :fabric:test --no-daemon --stacktrace` with `-p v2`. These tasks already exist; `NO-SOURCE` adapter tasks are not gameplay evidence.

- [ ] Create a workflow triggered by relevant pushes and pull requests, with filters for `v2/**`, the root wrapper files/directory and this workflow. Do not restrict PR target branches. Use `contents: read`, checkout `persist-credentials: false`, a 20-minute initial cold-build timeout and cancellation by PR/ref.
- [ ] Use verified action commit pins: checkout `3d3c42e5aac5ba805825da76410c181273ba90b1` (v7), setup-java `b843ebf9b913146b38da2eaa7aeddf76074ae1ad` (v6), setup-gradle `3f5f9adaf7d9fecd50b5935e54106014257a94e6` (v6), upload-artifact `cf430e030ddbb5b0abf93d22962f4752f3646cd9` (v7). For setup-gradle use `cache-provider: basic`; do not add a second Java cache.
- [ ] Capture console output under `v2/build/`, creating the directory first and preserving pipeline failure with Bash `pipefail`. Upload the console log plus core/Fabric reports and XML on failure. An early failure may have no XML; retain its console evidence.
- [ ] Validate YAML and task/shell configuration using available tools; run the exact Gradle task combination if it has not been verified together. Record local evidence and limits. Avoid test code that merely mirrors the YAML.
- [ ] Self-review, commit and obtain independent review. Publish the reviewed workflow in the foundation PR and inspect its actual hosted run before calling this CI slice complete. Keep parent Task 14 unchecked.

**Pass:** the hosted job runs the real core tests and architecture rules, compiles both Fabric source sets, preserves failures and reports its actual result. A YAML parse or local run alone cannot satisfy the hosted gate.
