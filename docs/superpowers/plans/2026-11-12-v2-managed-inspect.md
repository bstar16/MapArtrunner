## I3: work expiry, cleanup permission and the existing supervisor

One operation has phases `WORK → CLEANUP → SETTLED`; expiry invalidates WORK only. Host owns this phase transition atomically; one Commands worker owns the corresponding try/finally and no later operation is admitted until cleanup and publication settle. WORK is bounded by an absolute600000ms command deadline and existing fixture readiness/run/release tick budgets. waitTick waits for an actual later ordinary tick; the host never calls adapter.tick or Fabric's gametest phaser. Normal completion/failure also ends WORK before cleanup.

`beginCleanup` is permitted once for the same operation even if WORK expired. It issues a distinct nontransferable CLEANUP scope with its own <=10000ms absolute deadline, capped at WORK deadline+10000ms when work has already expired. cancelSession closes admission and invalidates ordinary scopes; it must not blanket-deny the separate cleanup transition. Cleanup may only perform Runner's freshly authority-checked owned key/control release, fault cancellation if actually owned, evidence reads/capture, Watch freeze and session-close handling. It cannot reset/restore/import/start/place. It cannot inherit another operation's world or scope. A replacement world gets zero stop/restore/capture effects; filesystem-only old diagnostics and old Watch freezing may still be retained. Failure of authority is recorded, not an excuse to call MapArtClient.stop on the replacement.

On timeout, the original timeout stays the operation's primary exception; release/capture/freeze failures are suppressed/retained under it. Completion does not become success because cleanup succeeded. On success followed by cleanup failure, the operation becomes failure. A failed screenshot with verified released controls/frozen recording is a settled cleanup with incomplete evidence; unresolved release/worker/phase settlement is not healthy idle and prohibits next admission. An ordinary callback already executing cannot be retroactively undone; queued callbacks delivered late must have zero effects. A late callback/completion never writes a newer result or evidence scope.
