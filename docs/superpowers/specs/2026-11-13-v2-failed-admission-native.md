### Encoding and three exact schemas

The following is the whole acceptance wire contract, not a generic extensible protocol. Fixed application marker is `MAPART_N1_V1 `. Each row is marker + one compact JSON object + LF, with no BOM, pretty-printing, embedded raw newline or trailing text. Use deterministic listed key order and JSON escaping (quotes/backslash/control characters escaped; valid non-ASCII encoded as UTF-8; reject unpaired surrogates). Reject duplicate/unknown/missing keys and wrong types. Every named key is present, including nulls. JSON booleans are booleans; integers below are JSON integers without exponent/fraction. A row has at most **8192 UTF-8 bytes including marker and LF**. Each retained physical Minecraft stdout record has at most **10240 UTF-8 bytes including its actual logger prefix and LF/CRLF**, with that prefix at most **1024 bytes**. Root retains/audits the complete actual prefix and terminator before extracting the marker; it must verify the observed Minecraft stdout envelope from the actual launch's log format/thread context, not assume a prefix from this source-only design or strip arbitrary leading text. Marker embedded in chat, exception text, another JSON string or an unverified envelope is not a row. One physical record must contain exactly one whole row. Prefix rewriting/splitting/truncation or incompatible encoding makes evidence insufficient.

Per-string UTF-8 limits **before JSON escaping**: schema/event/case/enum values64 bytes, canonical UUID36, canonical operation-directory string1024, SHA256 exactly64 ASCII hex, each fully qualified failure class256, each failure message512. These limits apply individually to every field of that kind, including nested failures. Escaped serialized bytes also count toward8192. Never truncate, replace invalid characters, round times or omit fields to fit. Over-limit/invalid values latch diagnostics failure. Validate all three schemas/size bounds in memory after effects before emitting any row (final emission time/previous-flush status are bounded fixed-format substitutions checked again). On failure emit no purported valid proof set; use the existing stderr diagnostic path with a fixed bounded error label, never the offending unbounded value.

All three objects have these exact first keys:
`schema,event,seq,case,sessionId,operationId,ordinal,command,occurredNanos,emittedNanos,diagnosticsComplete`.
Values are schema=`mapartrunner-n1-native-proof-v1`, event from the three names, seq1/2/3 respectively, case=`n1-header|n1-post-link`, canonical actual UUIDs, ordinal3, command=`RESET`, and diagnosticsComplete boolean. IDs/case/command must match across rows and genuine receipts/retained RUN2. Neither timestamp is nullable in an emitted row.

Time values are **JSON strings**, canonical signed decimal Java long values (no leading plus/zeros, no -0), checked within [-9223372036854775808,9223372036854775807]. Java serialization and Root reconstruction use exact signed64-bit/BigInt arithmetic, never IEEE-754 Number conversion. Native sources are the existing same-JVM System.nanoTime-backed clocks, not log arrival or injected clocks. See timing rules below.
